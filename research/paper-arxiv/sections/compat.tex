\subsection{Compatibility: One Gateway, Nineteen Ways In}
\label{sec:compat}

A demonstration that only works with the demonstrator's agent proves
little, so the same scenarios---the benign query of S1, a call the
agent is talked into that L1 catches, a destructive call a policy
holds for a second person, and, on every path that reports context, an
indirect injection through a tool return that only the provenance layer
can see (S4)---are run against nineteen harnesses: plain
SDK loops in three languages, six open-source frameworks, three
closed harnesses (the OpenAI Agents SDK on both of its APIs, the Claude
Agent SDK running the Claude Code runtime, Google's GenAI SDK), an
RL-trained open-weight model served locally, and the two non-SDK
transports (the MCP proxy and the egress proxy, the latter against both
OpenAI and a self-hosted model). Every row uses the integration the
paper describes and nothing else; the gateway is the shipping build; the
language-model calls are real. Appendix~\ref{app:compat} gives the matrix
(Table~\ref{tab:compat}) and the harness code is in the repository.

The exercise was worth more than the table. Running it found, and the
current version fixes, twenty-four defects that no unit test had caught; all are listed here: every SDK started a new hash chain at sequence zero in every
process, so an agent restarted once failed chain verification (the
Cockpit's chain counter, screenshotted against the matrix, showed it);
the violations table carried foreign keys that no pre-execution decision
can satisfy, so every \texttt{/check} block and hold was silently dropped
from the Cockpit's counts; the Go SDK's traces were in a shape the
gateway would have rejected, and never reached it anyway because the
process exited before the final flush; the MCP proxy's own trace record
had the same shape problem, so the transport that needs no SDK left no
audit record;
the Python SDK replaced any human-readable agent id with a
random UUID, so policies and approvals keyed to the agent's name never
matched; its OpenAI patch crashed on streaming responses and did not see
the Responses API or the current Google GenAI client at all; the
Pydantic~AI patch sat at the wrong layer and scanned the user's prompt
instead of the tool call; the LangGraph patch passed the ToolCall
envelope as the arguments, so policies matching on an argument never
fired; the CrewAI and AutoGen patches sat on methods their current
versions override or never call, so neither framework was guarded at
the tool; the Go SDK read a field the gateway does not send and blocked
every call; the JavaScript SDK treated a held call as a block instead of
waiting; the MCP proxy re-advertised output schemas it could not satisfy,
so strict clients rejected every result; the L1 shell-metacharacter rule
fired on the semicolon of an ordinary SQL statement; a free-tier agent
cap silently switched new agents to audit-only; and blocking mode held
failed validations for a person rather than blocking them. The S4
scenario, added in this version, found the next two: the SDK's request-side
context hook---the code that classifies each span of the messages array
and reports it to the gateway's ledger, on which the whole provenance
layer depends---was implemented and unit-tested and never called by
\texttt{auto()}, so every ledger stayed empty and no provenance rule had
ever fired outside its own tests; and L1's shell-metacharacter rule was
applied to every string argument of every tool, so the semicolon in an
injected email body was blocked as shell injection before the provenance
layer was asked, and the cell would have credited the wrong layer. The twenty-second is the most instructive, because the matrix itself had reported it as a pass. The Python SDK applies a \texttt{block\_threshold} (default
\texttt{HIGH}) to the gateway's risk tier before it reads the decision,
so a policy hold on a \texttt{LOW}-risk call was returned to the agent as
\texttt{allow}: the tool ran at once, the agent never waited, and the
approval queue filled with holds that nobody was waiting on. The S3
column had been scored from the approvals table, where the second
attendee's decision was duly recorded three seconds later; it was the
traces, which stayed at \texttt{PENDING\_APPROVAL} because no agent ever
resolved them, and the S3 wall-clock times, indistinguishable from S1's,
that gave it away. The SDK now honours \texttt{pending} and any rule-produced \texttt{block} regardless of tier, the matrix records how long each agent actually waited, and since this version the threshold's default enforces every block the gateway returns, as the evaluation's harness does and the JavaScript and Go SDKs always did. The twenty-third was the request-side hook missing from Anthropic's beta endpoint, which Pydantic~AI uses (Appendix~\ref{app:compat}). The twenty-fourth surfaced only at evaluation scale: a self-hosted gateway, with no Stripe and therefore every organisation on the hosted Free plan, refused every check past the plan's monthly quota (then 1{,}000); the matrix makes 98 checks over its 76 cells, AgentDojo about five thousand. Quotas now apply only where hosted billing is
configured. Each is the
kind of gap that appears only when a real framework drives the real
gateway, which is the argument for keeping the matrix in the repository
and running it on every release.
